# v0.3.0 — Bascule automatique vers un autre onglet au blocage quota

Date : 2026-09-23. Demande de Maxime : « quand j'ai plus de quota, ouvrir l'appli direct sur un autre onglet (DM par défaut sur Insta et Twitter) ». Choix validé : bascule automatique, onglet réglable par app, overlay seulement si la bascule échoue. La nuit n'est pas concernée (overlay comme avant).

## Comportement

- Quand la décision est `Block(Quota)` sur une cible (fil Instagram, Reels, fil X), Rehab touche l'onglet de repli de l'app au lieu d'afficher l'overlay.
- Onglet de repli par app : **Messages** (défaut), **Recherche**, ou **Désactivée** (= overlay comme avant).
- Si l'onglet n'est pas visible dans l'arbre (ex. barres masquées en défilant sur X) ou si, 1,5 s après la tentative, la cible est toujours à l'écran : overlay (comportement actuel, joker/relapse inchangés). Pas de nouvelle tentative tant que l'utilisateur n'a pas quitté la cible (sinon boucle de touchers).
- Un joker/relapse actif ou la nuit : inchangé. `Block(Night)` → overlay, jamais de bascule.
- L'usage n'est pas compté pendant la tentative (même règle que le blocage : `closeOpen`).

## Technique

- **rules** : `enum class RedirectTab { Messages, Search }` ; `PackageRules.redirectTabs: Map<RedirectTab, Matcher>`. Instagram : `Messages = ViewId("direct_tab")`, `Search = ViewId("search_tab")`. X : `Messages = AllOf(ContentDesc(^Messages$), NearBottom())`, `Search = AllOf(ContentDesc(^(Explorer|Explore|Rechercher|Search)$), NearBottom())`. `ScreenDetector.redirectBounds(snapshot, tab): Bounds?` (premier nœud qui correspond, bounds non vides).
- **Toucher** : `AccessibilityService.dispatchGesture` (tap de 50 ms au centre des bounds) — un seul mécanisme pour les deux apps (les onglets Compose de X ne sont pas `clickable`). Config du service : `android:canPerformGestures="true"`. Le tap passe même overlay affiché car la fenêtre d'overlay s'arrête au-dessus de la barre d'onglets (`navBarTop`).
- **Décision pure testable** (`app/.../service/RedirectPolicy.kt`, Kotlin pur) : état par package (`attemptAtMillis`, `failed`), entrées : décision, cible présente, bounds trouvés, onglet configuré, `nowMillis` ; sortie : `Redirect(bounds)` | `ShowOverlay` | `Wait` (tentative en cours < 1,5 s). Remise à zéro quand la cible disparaît ou que la décision n'est plus `Block(Quota)`. Confinée au thread moteur.
- **Réglages** : section « BASCULE AU BLOCAGE » avec une ligne par app (« Instagram » / « X », valeur « Messages » / « Recherche » / « Désactivée »), dialogue à choix unique. Stockage app (SharedPreferences `rehab_redirect`), pas dans `Settings` du domaine (ce réglage ne desserre aucun verrou : désactiver la bascule ramène l'overlay). Note : « Quand le quota est atteint, Rehab ouvre cet onglet au lieu d'afficher l'écran de blocage. La nuit, l'écran de blocage s'affiche toujours. »
- **Debug** : ligne « Bascule » dans « Dernière détection » (ex. « Messages · il y a 3 s » / « échec → overlay » / « — »).

## Tests

- rules : `redirectBounds` sur `ig_feed_followed.xml` et `ig_reels.xml` (direct_tab), `x_home_foryou.xml` (Messages en bas), `null` sur un snapshot sans barre.
- `RedirectPolicyTest` : première tentative → Redirect ; < 1,5 s → Wait ; ≥ 1,5 s cible toujours là → ShowOverlay et plus de tentative ; cible quittée → remise à zéro ; nuit → ShowOverlay ; onglet désactivé ou bounds absents → ShowOverlay ; joker actif (Allow) → rien.
